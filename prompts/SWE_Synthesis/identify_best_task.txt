The problem is divided into **four key steps**, with each step having its own distinct function:  
1. **Find Buggy Code**: This function will implement a LangGraph workflow that will use OpenAI gpt-4o-mini provided with file viewing & searching tools (through bot object, bot object has functions bot.getSearchTools() and bot.getContentViewingTools()) to search through the repository and find those files that may have bugs based on the problem statement. The problem will be from SWE Bench dataset and the function can access the problem through the *problem* object of SWEProblem class.

The LangGraph workflow will have a search_llm_node, search_tool_node between which the workflow will keep iterating until the search_llm finds the buggy files. After that a get_files_content node will use an llm to call get_files_content_tool_node to get the content of those buggy files that have been identified. This data (buggy_files_path, line_numbers, code) will be formed into a json object that will be dumped to env.swe_temp_path. The problem and env variables will be globals.

2. **Generate Solution Code**: This function will use the insights from the "Find Buggy Code" step to generate the solution code. It will rely on the LLM to produce the necessary modifications to fix the identified buggy code.  
3. **Apply Solution Code**: This function will use **OS tools** to apply the generated solution code to the relevant project files. The function will directly modify the source files and return an **Agentic workflow** representing this application process.  
4. **Validate Solution**: This function will run **pytest** on the modified files to ensure the applied solution resolves the bug. It will generate an **Agentic workflow** that orchestrates the pytest execution and checks if the bug is resolved.
